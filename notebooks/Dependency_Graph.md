## Phase 2: Dependency Engine & Sectoral Caching (`src/Model.wl`)

Архитектура ленивых вычислений (Lazy Evaluation) и точечной инвалидации кэша. Позволяет избегать монолитных пересчетов схемы при изменении независимых параметров.

* **`GetSectoralHashes[modelAssoc]`**
    Разбивает физические параметры схемы на три независимых домена (Сектора): `Kinetic` (емкости $C, C_J$), `Potential` (индуктивности и джозефсоновские энергии $L, E_J$) и `External` ($\Phi_{ext}$). Возвращает ассоциацию хешей от точных численных значений. Это защищает систему от ложных пересчетов при смене порядка параметров.

* **`$DependencyRegistry`**
    Глобальный граф вычислений. Содержит узлы (например, `"CompiledEngines"`, `"StaticMatrices"`, `"EquilibriumFluxes"`, `"PlasmonFrequencies"`). Каждый узел определяет:
    * `Dependencies`: список родительских узлов, которые нужно вычислить до него.
    * `RelevantHashes`: список физических доменов, от которых зависят данные (например, поиск равновесия зависит только от `"Potential"` и `"External"`, но игнорирует `"Kinetic"`).
    * `Compute`: чистая функция, вызывающая атомарные JIT-калькуляторы.

* **`GetNumericalQuantity[modelAssoc, keyString]`**
    Умный универсальный резолвер графа. 
    Принимает модель и строковый ключ нужной величины. Автоматически:
    1.  Проверяет `VersionedCache` модели.
    2.  Сравнивает текущие секторальные хеши с хешами в кэше.
    3.  Если кэш валиден — мгновенно возвращает результат.
    4.  Если данные устарели — рекурсивно спускается по дереву зависимостей, вычисляет только нужные узлы и обновляет кэш.

* **`GetParameterSymbols[modelAssoc]`**
    Вспомогательная функция для корректной генерации C-кода. Извлекает символьные переменные (без размерных констант и потоков равновесия) из подстановочных правил модели. Обеспечивает строгое совпадение паттернов (Pattern Matching) для JIT-компилятора `CalcCompiledEngines`.

## Phase 3: Smart Sweep Pipeline & Hot Loops (`src/Numeric/Numeric.wl`)

Инфраструктура горячих циклов для сверхбыстрого построения графиков и сканирования параметров, использующая Functional JIT и изолированные замыкания.

* **`GenerateSweepPipeline[modelAssoc, targetQuantity, OptionsPattern[]]`**
    Фабрика замыканий. Вместо того чтобы на каждом шаге графика опрашивать граф зависимостей и собирать хеши, эта функция один раз извлекает всю JIT-статику из `GetNumericalQuantity` и возвращает **чистую анонимную функцию (замыкание)** $f(\Phi_{ext})$, готовую для использования в `Plot` или `ParallelMap`.
    
    **Ключевые механизмы внутри замыкания:**
    * **Isolated Path History:** Хранит историю точек минимума `pathHistory` локально внутри себя. Это предотвращает Race Conditions (конфликты потоков) при параллельных вычислениях.
    * **Smart Predict (KD-Tree):** При получении новой точки $\Phi_{req}$, функция использует встроенный `Nearest` для мгновенного поиска ближайшей известной точки равновесия из истории, обеспечивая идеальный стартовый вектор для алгоритма Ньютона.
    * **Homotopy Continuation (Sub-stepping):** Защита от фазовых проскальзываний. Если запрошенная точка находится слишком далеко от ближайшей известной (расстояние больше `MaxFluxStep`, по умолчанию $0.05$), алгоритм автоматически разбивает путь на мини-шаги, прогоняя JIT для каждого промежуточного значения.
    * **In-place Flux Mutation:** Для максимальной скорости внешний поток изменяется напрямую (через индексы) внутри упакованного массива `paramVector` (C-массив), полностью исключая медленные символьные подстановки `/. rules` из горячего цикла вычислений.
